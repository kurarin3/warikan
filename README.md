# わりかん

メンバー・日付ごとに立て替えをまとめて、精算額と送金方法を自動計算するアプリです。
ビルド不要の静的サイト（HTML / CSS / ES Modules）で、データは Firebase Realtime Database に保存します。

公開先: <https://kurarin3.github.io/warikan/>

## 参考にしたアプリからの主な変更点

| 変更点 | 実装 |
| --- | --- |
| 4 人で割ったが均等にならなかった場合に、それぞれの支払い額を入力できる | 「複数人で支払った」モードで、1 項目にメンバーごとの支払い額を持たせられます。同じ項目を人数分登録する必要はありません。負担側も「均等割」と「個別に指定」を選べます |
| 対象メンバーはデフォルトで全員にチェック | 初期表示と項目追加後は全員チェック済み。あとから追加したメンバーも自動でチェックが入ります |
| 日付を管理して、過去にさかのぼって同じメンバーで管理できる | 項目ごとに日付を持ち、上部の日付バーで切り替えます。精算も「全期間」と「その日だけ」で切り替わります |
| ルームごとに 4 桁パスワードで入室制限 | ルーム作成時に 4 桁を自動生成（変更可）。入室時に照合し、共有ダイアログから変更できます |

## セットアップ

### 1. Firebase プロジェクトを用意する

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作成する
2. 「構築 → Realtime Database」でデータベースを作成する（ロケーションはどこでも可）
3. 「プロジェクトの設定 → マイアプリ」でウェブアプリ（`</>`）を追加すると `firebaseConfig` が表示される

### 2. 設定値を貼り付ける

`js/config.js` の `firebaseConfig` を、手順 1 で表示された値に置き換えます。
未設定のまま開くとセットアップ案内の画面が出ます。

### 3. セキュリティルールを設定する

1. Firebase コンソールの左メニューで **構築 → Realtime Database** を開く
2. 画面上部のタブ（データ / ルール / バックアップ / 使用状況）から **ルール** をクリックする
3. エディタの中身を `Ctrl+A` → `Delete` で全部消し、`database.rules.json` の内容をそのまま貼り付ける
4. エディタ上部の **公開** ボタンを押す（押すまで反映されません）

ルーム一覧の取得は禁止され、ルーム ID を知っている場合だけ読み書きできます。

公開後に「ユーザーがデータを読み書きできます」という警告が出ることがありますが、
このアプリはログイン機能を持たない設計なので想定どおりです。
テストモードでデータベースを作成した場合の「30 日後に期限切れ」という警告も、
このルールを公開すれば消えます。

正しく入ったかどうかは、ルールエディタの **シミュレータ**（ルールプレイグラウンド）で
`/rooms/abc` の読み取りが許可、`/rooms` の読み取りが拒否になることで確認できます。

### 4. 動かす

ES Modules と Web Crypto を使うため、ファイルを直接開く（`file://`）のではなく HTTP で配信してください。

```sh
python -m http.server 8000
# http://localhost:8000 を開く
```

公開するときは、このディレクトリをそのまま GitHub Pages などの静的ホスティングに置くだけです。
`main` ブランチに push すると GitHub Pages が自動で更新されます（反映まで 1 分ほどかかります）。

## 使い方

1. ルーム名・メンバー・4 桁パスワードを入れてルームを作成する
2. 「共有」から URL をコピーし、パスワードと一緒にメンバーに渡す
3. 日付と項目を入力していく
   - 1 人が全額立て替えたとき → **1 人が立て替え**
   - 何人かで出し合ったとき → **複数人で支払った** を選び、それぞれの金額を入力
   - 負担を均等にしないとき → **個別に指定** で 1 人ずつ金額を入力（支払い合計と一致しないと警告が出ます）
4. 「精算」で各自の差引と、誰が誰にいくら渡せばよいかを確認する

金額はすべて 1 円単位の整数で扱い、均等割の端数は先頭のメンバーから 1 円ずつ配分されるので、
負担額の合計は必ず支払い合計と一致します。

## パスワードについて

4 桁パスワードは **入室時の簡易的な鍵** です。ハッシュ（SHA-256）だけを保存し、
パスワード自体はデータベースにもブラウザにも残りません。
ただし照合はブラウザ側で行うため、ルーム ID を知っている人がデータベースへ直接アクセスすれば
中身を読むことは技術的には可能です。機微な情報は入れないでください。
本格的に保護したい場合は Firebase Authentication を導入し、ルールを認証ベースに変更してください。

## ファイル構成

```
index.html            画面（ロビー / パスワード入力 / ルーム）
css/style.css         スタイル（ライト・ダークの両対応）
js/config.js          Firebase の設定値（要編集）
js/db.js              Realtime Database の読み書き
js/storage.js         localStorage（ルーム履歴・入室状態）
js/calc.js            割り勘と精算の計算
js/app.js             画面の組み立てと入力処理
database.rules.json   Realtime Database のセキュリティルール
tests.html            計算ロジックのテスト（ブラウザで開くと結果が出ます）
```
